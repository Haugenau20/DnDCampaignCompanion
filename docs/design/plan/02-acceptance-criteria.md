# Acceptance criteria

One section per phase, written to be pasted as an issue. Each has a **gate** —
a single question that decides merge — plus fences naming what is *not* in
that phase.

A phase is done when its gate passes, not when it feels finished.

---

## Phase 0 — Foundations & bug fixes

`visual/phase-0-foundations`

**Gate: every list surface shows visible separation between rows, and no
element changed size or position.**

- [ ] CSS layer order declared explicitly, surface before state.
- [ ] `.selectable-item` no longer sets a resting background or border.
- [ ] Card and sunken surfaces render their own background everywhere they are
      applied — stat cells, activity rows, filter pills, quest items.
- [ ] The quest-progress cell's tint is visible, distinguishing it from the
      four count cells.
- [ ] Quest items in the Home aside have a visible border again.
- [ ] `Typography` no longer forces `leading-none` on body-level variants.
      Headings unchanged.
- [ ] The signed-out description paragraph sets with normal line height.
- [ ] Active nav item meets AA — was ~2.87:1 (`--color-primary` on
      `--hover-medium`).
- [ ] Hover and focus still work on every element touched.
- [ ] Keyboard focus visible on all of them.

**Not in this phase:** no new tokens, no colour changes beyond the nav fix, no
markup restructuring, nothing dark.

## Phase 1 — Token model restructure

`visual/phase-1-tokens`

**Gate: screenshots before and after are identical, in every theme.**

If anything differs, either the restructure is wrong or a fallback is missing.
Do not "fix" a difference by adjusting a value.

- [ ] Tokens are nested objects; variable names derive from paths.
- [ ] The positional declaration/`setProperty` map is gone — variables are
      generated by traversal.
- [ ] Surface pairs exist for chrome, page, card, sunken, band; each defines
      bg, on, on-muted, border.
- [ ] Every new token falls back per `01-token-model.md` §5.
- [ ] Dark and medieval render exactly as before, unmigrated.
- [ ] Ambiguous paths are rejected, not silently resolved.
- [ ] Every consumed variable is enumerable and checkable against the
      generated set.
- [ ] Contrast verified once per pair, per theme, and recorded.

**Not in this phase:** no visual change, no dark chrome, no sigils, no
ornament tokens, no package extraction.

## Phase 2 — Global chrome

`visual/phase-2-chrome`

**Gate: no `[data-theme=…]` rule remains for anything a surface pair can
express, and every out-of-scope page still reads correctly.**

- [ ] Header consumes the chrome pair; it names no colour directly.
- [ ] Footer likewise.
- [ ] `[data-theme="light"] .header-title` and its siblings deleted.
- [ ] Default theme chrome is dark; nav, search trigger, keyboard hint and
      avatar chip all take ink from the pair.
- [ ] Dark and medieval fall back and look as they did.
- [ ] Every out-of-scope page checked under the new chrome: Story, Quests,
      Rumors, NPCs, Locations, Notes, auth, signed-out.
- [ ] Active vs inactive nav distinguishable without relying on hue alone.
- [ ] All chrome text AA; icons and dividers 3:1.
- [ ] Theme switching still works from within the chrome.

**Not in this phase:** Home's hero band, sigils, ornament.

---

## Phase 3 — Entity sigils

`visual/phase-3-sigils`

**Gate: the same entity produces the same mark everywhere it appears, across
reloads.**

- [ ] Entity palette is an ordered collection token, tuned per theme.
- [ ] A mark derives deterministically from entity id.
- [ ] Every palette entry is legible against the same ink; verified.
- [ ] `--location-type-*` retired, its cases served by the palette.
- [ ] Appending a palette entry does not change existing marks.
- [ ] Marks never carry meaning alone — type is always also stated in text.
- [ ] Decorative marks hidden from assistive tech.

**Not in this phase:** bitmap imagery, uploads, avatars from user content.

---

## Phase 4 — Home composition

`visual/phase-4-home`

**Gate: Home reads correctly with an empty hero slot and with a long campaign
name, at both narrow and wide widths.**

- [ ] Hero band composed; campaign identity legible over it.
- [ ] Empty slot shows the designed fallback — not a broken image, not a gap.
- [ ] Long campaign name truncates as the source component does; header stays
      one line.
- [ ] Stats strip, activity list and quests aside recomposed on surface pairs.
- [ ] Ornament comes from tokens; no literal sizes or inline hex.
- [ ] Redundant encoding removed — a row states its type once.
- [ ] Empty and loading states designed for each region, not left blank.
- [ ] Reflows without horizontal scroll at the narrowest supported width.
- [ ] Full contrast audit of Home.

**Not in this phase:** bitmap plates, Storage, licensing, other pages.

---

## Phase 5 — Value tuning → pick 2a or 3a

`visual/phase-5-tuning`

**Gate: the choice is recorded with a reason, and only token values changed to
reach it.**

- [ ] Accent count and placement decided on real campaign data.
- [ ] Sigil saturation decided against a full-length list, not four rows.
- [ ] Diff contains token values only — no markup, no structure.
- [ ] Contrast re-audited after tuning; values shift ratios.
- [ ] Choice and reasoning in `03-drift-log.md`.
- [ ] Shape decisions written into `theme-contract` as ADRs.

**Not in this phase:** anything structural. If tuning needs a structural
change, it belongs in an earlier phase or a later project — log it.

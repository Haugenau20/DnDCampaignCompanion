Do first: T046 → T023 (the loader cluster)

  NPCsPage holds a second, independently fetched copy of the NPC collection, so a write through the
  context updates the provider's copy while the page keeps rendering the other one. That's the
  stale-stance bug you already saw. It's currently patched, not fixed — the ladder was wired to an
  onNPCUpdate prop that had been declared and never called — and T046 says plainly that every other
  write path in that directory has the same exposure.

  The real fix is T023's: drop the second loader, read the provider, add refreshNPCs to
  NPCContextValue (the other three contexts already expose theirs). That single change:

  - closes a defect class rather than one symptom — the next write path you add can't reintroduce it
  - halves the Firestore reads on that page
  - gives you the pattern to apply to SearchContext, which builds its own chapter/NPC/location/rumour
    hooks instead of consuming the providers

  T046 is sized S, T023 M. Doing T046 as T023 is the right call — the S version is the patch you
  already have.
